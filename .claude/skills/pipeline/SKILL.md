# Pipeline — этапы создания ролика

Главный принцип: **никогда не делать весь ролик сразу и никогда не анимировать до согласования**. Каждый этап пользователь смотрит сам, согласует или пишет правки. Правки записываются через скилл `qa`.

Перед КАЖДЫМ этапом прочитать:
- скилл `qa` (чек-лист ошибок);
- `ANIMATION_RULES.md` (технические правила);
- `references/REFERENCE.md` (эталонные ролики: к этому качеству и стилю стремимся).

## Инструменты просмотра

Проект ролика = копия `film-template/` → `films/<имя-ролика>/`.

1. **`review/Согласование.html`** — интерактивное согласование (этапы 1–4). Один файл, всё внутри, открывается двойным кликом без интернета.
   - Слева этапы и элементы со статусом (✓ согласовано, • черновик).
   - Мышь крутит камеру, **WASD/QE** — свободный полёт, Shift — быстрее.
   - На расстановке — кнопки 🎥 камер будущих кадров и рамка 9:16, показывающая, что попадёт в кадр.
   - Поле «Правки» у каждого элемента и кнопка «📋 Скопировать все правки» — пользователь вставляет их в чат.
   - Собрать: `npm run review`. После каждого изменения пересобрать и прислать файл пользователю.
2. **Плеер (Remotion Studio)** — `Запустить плеер (…)` или `npm run player`. Папки: `1-Characters`, `2-Objects`, `3-Locations`, `4-Staging`, `5-Parts`, `6-Film`. Понравилось → кнопка **Render**.

В облаке я проверяю всё сам (`tools/cloud.sh still …`, playwright для review.html) и присылаю картинки. Решение «согласовано / рендерим» принимает пользователь.

## Этап 0 · Бриф

Вход: сценарий, текст, озвучка или идея.
1. Пересказать: о чём ролик, длительность, тон, формат (по умолчанию вертикальный 9:16, ~60 с, как эталоны).
2. Разбить на **части по 20–30 с**: таблица «часть → секунды → что происходит → локация → персонажи → объекты».
3. Составить списки: персонажи, **объекты** (реквизит, транспорт, оружие, мебель, вывески), локации.
4. Озвучка: части режутся по фразам и паузам. Платное распознавание речи — только с разрешения.
5. Вопросы одним списком.

Выход: `films/<имя>/BRIEF.md`. **Ждать согласования.**

## Этап 1 · Персонажи

1. Каждый персонаж в `src/project.ts` (`CAST`): внешность по эталону (белая голова, тело-пилюля, ноги-палочки, аксессуары), одежда, роль, `status: 'draft'`.
2. Показать в review.html (все рядом и каждый отдельно) и в плеере `cast`.
3. Правки → исправить → записать в `qa` → показать снова. Согласован → `status: 'approved'`.

## Этап 2 · Объекты

1. Каждый объект в `src/objects/` (`OBJECTS`): сделан кодом **или** взят из модели пользователя.
   - Модели: GLB/GLTF кладём в `public/models/`, подключаем `<Model file="models/x.glb" height={…} restyle="toon" />`. FBX конвертировать в GLB (`npx fbx2gltf`). Масштаб задаём реальной высотой (1 м = 2.2 ед.).
   - Стилизация на моё усмотрение по эталону: контур, мультяшный свет, палитра. Можно оставить родные материалы (`restyle="keep"`).
   - Текстуры и надписи (бочки, ящики, вывески) — как в эталоне: реквизит рассказывает историю.
2. В review.html каждый объект показан рядом с человеком для масштаба (человек ставится автоматически рядом, не внутри).
3. Согласовать каждый объект.

## Этап 3 · Локации

1. Каждая локация в `src/locations/` — декорации без действия, максимально детально (текстуры, реквизит, свет, время суток, как в эталоне). Сложные здания можно собирать из ассетов пользователя.
2. В review.html — свободный полёт по локации. В плеере — облёт `loc-<id>`.
3. Согласовать.

## Этап 4 · Расстановка (без анимации)

Для каждой части ролика — `src/staging/` (`STAGINGS`):
1. Где стоит каждый персонаж и объект в локации.
2. **Взаимодействия** в виде статичных поз: кто сидит в машине, кто держит пистолет или кружку, кто на скамейке, кто за столом. Предметы в руках через `holdL/holdR`, посадка через `sit()`, без прониканий.
3. Камеры будущих кадров (`shots`): название, позиция, цель, fov, заметка «что показывает кадр».
4. Показать в review.html: пользователь летает вокруг, жмёт 🎥 камеры с рамкой 9:16. В плеере — `staging-<part>` (по 2 с на камеру).
5. Согласовать каждую часть. **Только после этого — анимация этой части.**

## Этап 5 · Анимация частей (по 20–30 с)

Для каждой согласованной расстановки по очереди:
1. Анимировать в `src/parts/` (`partNN`): движение от согласованных поз, камеры по согласованным кадрам, мимика, эффекты, звук, субтитры по слову (как в эталоне, если нужны).
2. Самопроверка по `qa`: кадры каждые 2 с плюс полный рендер превью.
3. Пользователь смотрит `partNN` в плеере. Правки → `qa` → снова.
4. Согласована → `status: 'approved'`, следующая часть. Согласованные части не трогать без просьбы.

## Этап 6 · Финал

1. `film` = согласованные части по порядку (120 FPS). Проверить стыки: свет, позиции, звук.
2. Пользователь жмёт Render в плеере или `npm run render`.
3. Итог: какие новые правила появились в `qa`.

## Общение

- В конце этапа: что сделано, какой файл открыть (`review/Согласование.html` или композиция в плеере), 1–3 вопроса.
- Статусы вести в коде (`status`) и кратко в `BRIEF.md`.
- Русский язык, простые слова.
