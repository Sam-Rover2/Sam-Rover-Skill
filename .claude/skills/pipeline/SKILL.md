# Pipeline — этапы создания ролика

Главный принцип: **никогда не делать весь ролик сразу**. Каждый этап показываем в плеере, пользователь согласует или даёт правки, и только потом следующий этап. Правки записываются через скилл `qa`.

Перед КАЖДЫМ этапом: прочитать скилл `qa` (чек-лист) и `ANIMATION_RULES.md`.

## Плеер

Проект ролика = копия папки `film-template/` → `films/<имя-ролика>/`.

Плеер — Remotion Studio. Пользователь запускает его сам:
- Windows: `Запустить плеер (Windows).bat`, Mac: `Запустить плеер (Mac).command` (или `npm run player`);
- в плеере папки этапов: `1-Characters`, `2-Locations`, `3-Parts`, `4-Film`;
- понравилось → кнопка **Render** в плеере (или `npm run render`), MP4 в `out/`.

Я в облаке проверяю всё сам через `tools/cloud.sh still …`/`render …` и присылаю кадры или превью MP4. Но решение «нравится / рендерим» принимает пользователь в своём плеере.

## Этап 0 · Бриф

Вход: сценарий, текст, озвучка (аудио) или идея.
1. Прочитать и пересказать своими словами: о чём ролик, длительность, тон, аудитория.
2. Разбить на **части по 20–30 секунд**: таблица «часть → секунды → что происходит → локация → персонажи».
3. Список персонажей (кто, роль, характер) и список локаций.
4. Озвучка: если есть аудио, части режутся по паузам и фразам, а тайминги берутся из аудио. Платные сервисы распознавания речи — только с разрешения пользователя.
5. Уточнить неоднозначности одним списком вопросов.

Выход: создать `films/<имя>/BRIEF.md` (части, персонажи, локации). **Ждать согласования.**

## Этап 1 · Персонажи

1. Описать каждого персонажа в `src/project.ts` (`CAST`): внешность, одежда, роль, `status: 'draft'`.
2. Показать: композиция `cast` в плеере (все рядом, медленно поворачиваются) плюс присланная картинка.
3. Правки → исправить → записать в `qa` → показать снова.
4. Согласован → `status: 'approved'`.

**Не переходить к локациям, пока все персонажи не согласованы.**

## Этап 2 · Локации

1. Каждая локация — набор декораций без действия (`src/locations/`), с облётом камеры (`loc-<id>`).
2. Проверить по `qa`: масштаб, 8–12 деталей, свет и время суток.
3. Показать, правки, согласовать → `status: 'approved'`.

**Не начинать анимацию, пока локации не согласованы.**

## Этап 3 · Части ролика (по 20–30 с)

Для каждой части по очереди:
1. **Раскадровка:** 4–8 ключевых кадров (stills) с подписями «что происходит, какая камера». Согласовать (быстро, без анимации).
2. **Анимация части** (`src/parts/`, `partNN`): движение, камера, мимика, звук этой части.
3. Самопроверка по `qa` (кадры через каждые 2 с плюс полный рендер превью части).
4. Показать: пользователь смотрит `partNN` в плеере. Я присылаю превью MP4 и контактный лист.
5. Правки → исправить → записать в `qa` → показать снова.
6. Согласована → `status: 'approved'` и переход к следующей части.

**Следующую часть не начинать, пока текущая не согласована.** Согласованные части больше не трогать без просьбы пользователя.

## Этап 4 · Финал

1. `film` собирает согласованные части по порядку. Проверить стыки (свет, позиции персонажей, звук).
2. Общий звук: музыка и шумы по всем частям.
3. Пользователь смотрит `film` в плеере и нажимает Render (120 FPS). Либо я даю команду `npm run render`.
4. Итог: какие новые правила появились в `qa` за этот ролик.

## Как общаться на этапах

- В конце каждого этапа: что сделано, что открыть в плеере (точное имя композиции), 1–3 вопроса на решение.
- Статусы всех элементов вести в коде (`status`) и кратко в `BRIEF.md`.
- Язык — русский, простыми словами.
